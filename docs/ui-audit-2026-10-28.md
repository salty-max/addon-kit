# Audit of the addons' UI claims against the pinned source (28 October 2026)

Run with `wow-data/bin/ui.ts` (the pinned Gethe source, Era `classic_era@4192ac6`
= build 70576 exactly, Forever `forever@ca8368f` = 70532, the client being
70658) and the client's own interface file list (`ManifestInterfaceData`,
exact for both pinned builds). Method: every quoted `Interface\...` path in
the addons' Lua (hearthtale, codex, yonder, second-wind, keyring, palaver,
mealbook, goodwill, yours-truly, wow-locker, the kit), every `Icons\` name,
the Blizzard frame globals and keyed paths, and the Blizzard functions called.
The scripts are throwaway; the tool is `ui.ts`. The frames section was rerun after the reviewer's fixes to the resolver (keyed paths go through containers only; `$parent` names of nested templates): same results.

## Textures: nothing wrong

All of them exist in both games' client files except:

- `hearthtale/addon/test/game.lua:278` `Interface\Icons\Tree`: not a game
  file in either. A test fixture (a mock icon), never shipped. Harmless.
- Paths built by concatenation, checked by hand: Yours Truly `Panel.lua:249-251`
  `UI-SpellbookIcon-{NextPage,PrevPage}-{Up,Down,Disabled}` (all six exist in
  both games), the addons' own `Interface\AddOns\...\Media\...` (not the
  game's).
- Goodwill's four achievement icons (`Achievements.lua:18-21`: `INV_Misc_Note_01`,
  `INV_Banner_02`, `INV_Misc_Book_11`, `INV_Scroll_05`), `Ability_DualWield`
  (`FactionsBook.lua:152`) and `GossipFrame\AvailableQuestIcon`
  (`FactionsBook.lua:13`): all exist in both. Their art (what they look
  like) is not checked here: the mirrors' pictures are 2020 and 2022.
- Yours Truly's `MailFrame\UI-MailFrameBG`, `MailItemBorder` (`Panel.lua:159,
  192, 197`): exist in both.

## Frames

Confirmed in the source (both games unless said):

- `MiniMapMailFrame` (Era only, `Blizzard_Minimap/Classic/Minimap.xml:95`,
  hidden, 33x33) and `MinimapCluster.IndicatorFrame.MailFrame` (Forever only,
  with its `MailIcon` key): `yours-truly/.../Minimap.lua:23-25` and
  `docs/architecture.md:109` ("from the source, not yet seen in the
  client"): **confirmed in the source**, the doc now says so. Both of Forever's
  platform folders (`Camelot/`, `Mainline/`) define it.
- `MailFrame`, `InboxFrame`, `OpenMailFrame`, `MailFrame.Bg`, `MailFrameInset`
  (named for `ButtonFrameTemplate`'s `$parentInset`: the tool needed to learn
  that): all there. Differences worth knowing: Era's `InboxFrame` is 384x512
  anchored TOPLEFT and `OpenMailFrame` anchors to `InboxFrame` TOPRIGHT;
  Forever's `InboxFrame` is `parentKey="InboxFrame"` of `MailFrame` (anchored
  TOPLEFT/BOTTOMRIGHT) and `OpenMailFrame` anchors to `MailFrame` TOPRIGHT
  offset 46,0 (`Panel.lua:77-115` already branches on this).
- Palaver: `GossipFrame`, `QuestFrame`, `ItemTextFrame`, `QuestInfoFrame`
  (`.itemChoice` is set by Blizzard's own code in both), `AlertFrame`, the
  alert subsystem calls (`AddQueuedAlertFrameSubSystem`,
  `AddAutoAnchoredSubSystem`, `UpdateAnchors`) and `CustomGossipFrameManager`
  (Forever only, `Mainline/CustomGossipFrameBase.xml:38`; `Core.lua:83` guards
  it): confirmed. Its doc's four file names exist in both sources
  (`GossipFrameShared.lua` Shared; `QuestFrame.lua`, `QuestInfo.lua` in
  `Vanilla/` for Era: Era's source also carries `Classic/`, `TBC/` and
  `Wrath/` folders, read which one the TOC loads).
- The kit's `AlertFrame` join (`Kit.lua:2024-2031`): the API exists in both.

## Cannot be confirmed from the source

- **Era's C-side API**: the source has no API documentation for Era (no
  `Blizzard_APIDocumentationGenerated`), so these are neither confirmed nor
  contradicted for Classic Era, all behind a guard in the code (`if X then`):
  `C_Map.GetPlayerMapPosition` (codex Core.lua:136, Scan.lua:32,
  Unlocks.lua:266 …), `C_QuestLog.GetInfo/GetNumQuestLogEntries`
  (yonder Creatures.lua:472-473), `C_Reputation.GetFactionDataByID`
  (codex Unlocks.lua:312, goodwill Core.lua:102, with `GetFactionInfoByID`
  as the Era path, Core.lua:108), `C_Minimap.GetViewRadius`
  (yonder MinimapCircles.lua:34), `C_Seasons.GetActiveSeason`
  (kit Kit.lua:3043), `GetCameraZoom` (palaver Camera.lua:138 …, absent
  from both sources: C-side), `GetPlayerFacing`, `GetLootSourceInfo`,
  `GetSpellBaseCooldown`, `GetRewardSpell` (palaver Game.lua:190, guarded).
  A real test in the game settles them; the tool can't.
- Forever lacks the old trade-skill calls the source defines for Era
  (`GetNumTradeSkills`, `GetTradeSkillInfo`, `GetTradeSkillLine` …;
  mealbook Core.lua:157-164): Mealbook already takes `C_TradeSkillUI` on
  Forever (Core.lua:144-149). Consistent.
- Forever's source is 126 builds behind its client: a frame added in the
  last week is not in it.
